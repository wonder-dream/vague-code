## 一、教学规则（铁律）

1. **不按文章顺序讲**：`docs/articles/` 只是资料库，我按自组织路径（见下）教学，文章仅作该环节参考。
2. **全精讲**：所有阶段逐点讲透，不跳内容。
3. **面试导向**：
   - 重点：**架构设计题**（讲清取舍）+ **简历深挖**（数字 + 机制都能答）。
   - 源码细节题（如某行正则、某函数签名）**不会考，不必深挖到行级**——除非涉及机制正确性。
4. **节奏**：每阶段控制在 **40 分钟** 内学完，配 A/B/C 三档思考题，答完批改、搞清楚即结束。用户自己有番茄钟，不要拖堂。
5. **作业批改**：三档题逐题批改，答错的展开讲；关键考点（配对不变式、0 索引、熔断语义等）要确认内化。
6. **发现即记录**：教学中发现的代码/文档偏差、疑点，即时写入 `docs/known-issues.md` 或本文件"待跟进"，不丢。
7. 用户即项目作者，设计问题可讨论但改动需用户确认。
